# Upgrading from Wappa 0.34.0 to 0.34.1

This patch has one **breaking** change: the `IIdentityResolver` signature. If your Host has no custom resolver and doesn't build the state services or call `resolve_event_user_id` itself, nothing in your code needs to change.

## 1. The identity resolver takes an `InboxRef`

Before, the same resolver received a raw `inbox_id` from scheduled dispatch and API events, and a qualified cache namespace (`whatsapp__123`) from API state and Template state. A resolver could not tell Platforms apart, and stripping the prefix could not separate raw IDs that collide across Platforms.

```python
# 0.34.0
async def resolve(self, recipient: str, *, inbox_id: str) -> str: ...

# 0.34.1
async def resolve(self, recipient: str, *, inbox_ref: InboxRef) -> str: ...
```

Key your lookup on the whole `inbox_ref`, and take the Platform from `inbox_ref.platform`, never from the shape of `recipient`: it can be numeric on any Platform. The argument is runtime scope, not authority and not a cache namespace.

Two more signatures follow:

- `HandlerStateService(cache_factory, *, inbox_ref, identity_resolver=None)` and `TemplateStateService(cache_factory, *, inbox_ref, identity_resolver=None)` now require `inbox_ref`. Hosts using the prebuilt dependencies get it automatically.
- `resolve_event_user_id(recipient, explicit_user_id, fastapi_request, *, inbox_ref)` takes `inbox_ref` instead of `inbox_id`.

Update resolver fakes in your tests too. Search: `inbox_id: str) -> str`, `HandlerStateService(`, `TemplateStateService(`, `resolve_event_user_id(`.

**The webhook path does not call the resolver**, in this release or earlier. It keys the handler by `webhook.user.user_id`. The resolver runs on scheduled dispatch, `self.scope`, API events, API handler state and Template state. If your Host wants a canonical User on webhooks, it maps that itself in its handler.

## 2. Reconnect after a full offboard

`account_reconnected` now reaches `process_inbox_connection` when the Inbox is known and inactive ([ADR-0032](../adr/0032-inactive-inbox-reconnect.md)). It was refused with 400 before. On that delivery `self.messenger`, `self.whatsapp` and `self.instagram` are `None`, so check for it:

```python
async def process_inbox_connection(self, webhook):
    if webhook.state is not InboxConnectionState.RECONNECTED:
        return
    host_store.put(new_active_record)                    # 1. your decision and commit
    await runtime.directory.refresh_inbox(self.inbox_ref)  # 2. then refresh Wappa
    async with self.scope() as ready:                    # 3. only if you send now
        ...
```

Your directory source must list inactive records under the account, as its contract says. Make recovery idempotent, because Meta can repeat the event.

## 3. Namespace migration CLI

`wappa migrate cache-namespaces` exits with status 1 when any destination conflict remains, on a dry run too. A script that ignored conflicts now sees a failure. `--json` prints the complete report on stdout; text output still shows the first 20 of each list and says how many it hid.
