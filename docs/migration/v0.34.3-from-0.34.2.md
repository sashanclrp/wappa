# Upgrading Wappa 0.34.2 to 0.34.3

Rename deployment variables before restarting every worker. Copy values unchanged, then delete the old keys from the process environment and `.env`; even an empty retired key blocks startup. Setting both names also fails. Wappa never reads old names as aliases and never prints their values in migration errors.

| Retired name | Replacement |
| --- | --- |
| `WP_WEBHOOK_VERIFY_TOKEN` | `META_WEBHOOK_VERIFY_TOKEN` |
| `WP_ACCESS_TOKEN` | `META_WHATSAPP_ACCESS_TOKEN` |
| `WP_PHONE_ID` | `META_WHATSAPP_PHONE_NUMBER_ID` |
| `WP_BID` | `META_WHATSAPP_BUSINESS_ACCOUNT_ID` |
| `WAPPA_STRICT_META_SCHEMA` | `SYSTEM_STRICT_META_SCHEMA` |
| `OPENAI_API_KEY` | Host-owned `LLM_PROVIDER_OPENAI_API_KEY`; Wappa's setting was removed |

Explicit Inbox routing still rejects all three `META_WHATSAPP_*` credentials; use the Directory Source instead. `META_APP_SECRET` and `META_WEBHOOK_VERIFY_TOKEN` configure the Meta callback in either routing mode. Python settings attributes for the callback and WhatsApp bundle are unchanged. Wappa removes `settings.openai_api_key` and the `platform_configs.openai` detailed-health field; provider readiness belongs to the Host.

All existing `SYSTEM_*`, `META_*`, `REDIS_*`, `PORT`, `DATABASE_URL` and `REDIS_URL` names remain unchanged. Host examples use `CRM_API_TOKEN`, `CRM_WEBHOOK_SECRET` and `LLM_PROVIDER_OPENAI_API_KEY` for their own settings; these are not Wappa configuration. Refresh existing Host skills manually because `wappa init` preserves existing skill folders. No cache or database migration is required.
